# Fingerprint Browser UI 美化与交互改造方案

日期：2026-09-23。状态：P1（外壳与视觉基线）、P2（核心工作流）、P3（其余页面）、P4（细节与验证）已实施，见第 12 节。

本方案最初基于 Rust + GPUI Kit 0.6.4 界面源码及退出、生命周期文档制定。第 1–11 节记录设计目标，第 12 节记录 P1–P4 实施及已有 Linux 实机截图，第 13 节记录提交后审查与收尾。Windows 字体、缩放和窗口装饰等未验证项仍以第 12 节清单为准。

## 1. 设计结论与范围

推荐方向：克制、清晰、紧凑的专业桌面管理工具。用统一的信息层级、对齐、语义颜色、线性图标和状态反馈建立成熟感。主界面优先回答三个问题：哪个环境、现在什么状态、下一步可以做什么。

首轮保留现有五个页面和业务能力，不引入仪表盘、团队协作、多选批量操作等新产品范围。沿用 GPUI，不为美化更换技术栈。深色和浅色同时设计，保留用户已保存的主题选择。

优先决策：

1. 移除应用内容顶部的退出按钮，保留系统标题栏及窗口 X。
2. 删除重复的内容头部，将品牌放到侧栏，技术栈与完整版本说明收进设置中的“关于”。系统标题栏仍可保留真实版本，便于问题截图定位。
3. 统一图标家族与按钮层级；主操作保留文字，辅助操作使用带提示的图标。
4. 环境列表采用列对齐的紧凑列表；每行只展示当前有效的主操作，低频动作收进更多菜单。
5. 详情按需展示，设置与编辑表单按任务分组。

## 3. 窗口框架与退出行为

### 3.1 标题栏

第一阶段保留原生标题栏和系统最小化、最大化、关闭按钮，不自绘第二套窗口控件。这样可继续使用系统拖动、双击最大化、贴边布局和缩放行为。

删除内容区原 `header()`；侧栏顶部放 24–28 的品牌标识与产品简称。品牌标识优先整理现有 `assets/icon.png` 的小尺寸表现，不在本轮重做品牌。侧栏底部可放低强调的版本信息或关于入口，避免多处重复版本。

无边框一体式标题栏仅作为后续可选项，前提是完成 Windows / Linux 的拖动热区、窗口菜单、最大化、缩放和主题适配验证。

### 3.2 关闭窗口与真正退出

视觉入口精简不等于改变已有进程生命周期。窗口 X 继续遵循现有“每次询问 / 后台运行 / 保留浏览器运行 / 停止全部”的偏好与决策。

| 入口 / 选项 | 界面文案建议 | 行为 |
| --- | --- | --- |
| 窗口 X | 使用系统关闭控件 | 按已保存的关闭策略执行；默认询问 |
| 关闭对话框选项一 | 在后台运行 | 隐藏管理窗口，继续管理浏览器及代理进程 |
| 关闭对话框选项二 | 退出管理器，保留浏览器 | 管理器结束，浏览器及代理继续运行；明确后续接管含义 |
| 关闭对话框选项三 | 停止全部并退出 | 停止浏览器和代理后退出，使用危险操作样式 |
| 托盘菜单 | 显示窗口 / 停止全部并退出 | 保留后台恢复入口，完整退出文案与实际行为一致 |
| 侧栏品牌更多菜单 | 关闭窗口… / 停止全部并退出… / 关于 | 提供低频可发现入口；完整退出在存在活动任务时明确说明影响 |

关闭对话框宽约 480–560：标题“关闭 Fingerprint Browser”，一行实际运行数量，三项等宽、图标加标题加后果说明，底部“记住此选择”与取消。优先保持现有点击选项即可执行的行为，避免一次视觉改版引入不必要的步骤变化；不默认聚焦危险选项。取消或 Esc 只关闭对话框。

专项问题：当前 `enter_background` 在托盘创建失败后仍会隐藏窗口。应验证各桌面的恢复路径；若无法保证用户重新打开窗口，应保持窗口可见并给出就地提示。这是退出交互的可靠性修复，单独验收。

## 4. 页面布局与密度

推荐基准保持当前 1200 × 680，最小窗口继续以 960 × 560 为设计约束，尺寸单位为逻辑像素。

```text
┌ 系统标题栏：Fingerprint Browser · 真实版本 ────────── 窗口控件 ┐
│ 品牌          │ 浏览器环境   12 个 · 3 个运行中      ＋ 新建环境 │
│               │ 搜索名称或代理…                              │
│ 图标 环境     │──────────────────────────────────────────────│
│ 图标 代理     │ 环境 / 内核       代理       状态       操作   │
│ 图标 内核     │ 工作环境 A        香港节点   运行中     停止 ⋯ │
│ 图标 活动日志 │ 工作环境 B        直连       已停止     启动 ⋯ │
│               │ 工作环境 C        日本节点   启动失败   重试 ⋯ │
│               │                                              │
│               │         按需打开详情；默认让列表占满内容区     │
│ 图标 设置     │                                              │
└───────────────┴──────────────────────────────────────────────┘
```

这是信息结构线框，符号仅表示图标位置；交付实现使用统一矢量资源，不使用字符图标。

- 侧栏：推荐宽 200，内边距 12；导航行高 36–40，图标 18，图文间隔 10。
- 内容：外边距 24，小窗收至 16；页面标题、工具栏、列表之间间距 16–20。
- 页头：左侧标题与轻量数量摘要，右侧一个主操作；不添加巨大的数据统计卡片。
- 列表：默认行高 64，允许两行信息；异常详细内容展开显示，不让整张列表被错误文本撑乱。
- 详情：可关闭、标题明确显示所选环境；选中状态与面板内容始终一致。
- 宽度达到约 1280 且主列表能保留至少 720 时，可使用 360–400 宽的停靠详情。更窄时用覆盖式侧面板，保留足够阅读宽度和明确返回按钮。
- 960 宽时，把次要内核信息放到名称第二行，代理端点放到详情，始终保留环境名、状态、操作；不依赖横向滚动完成启动停止。
- 弹窗最大高度受窗口约束，内容可滚动、标题和操作区固定；不能依赖增大最小窗口掩盖溢出。

## 5. 视觉基础规范

### 5.1 颜色

推荐中性灰为主体，蓝色只承担主操作、选中与焦点。绿色表示运行或验证成功，橙色表示等待或警告，红色表示故障和真正的破坏性动作。正常停止使用中性按钮，不在每行常驻红色填充。

下表是起始候选，实施时应计算实际前景 / 背景组合对比度，而非直接认为配色已经验收。

| 语义 token | 浅色候选 | 深色候选 | 用途 |
| --- | --- | --- | --- |
| canvas | `#F6F7F9` | `#15171C` | 工作区背景 |
| surface | `#FFFFFF` | `#1D2027` | 列表、表单 |
| surface-raised | `#FFFFFF` | `#252932` | 菜单、弹窗 |
| surface-hover | `#EEF1F5` | `#2B303A` | 悬停反馈 |
| border-subtle | `#E2E6EC` | `#343A46` | 分隔线 |
| text-primary | `#202632` | `#EDF0F5` | 标题与主要内容 |
| text-secondary | `#596579` | `#AAB4C3` | 元信息与说明 |
| accent | `#2563EB` | `#3B82F6` | 强调、焦点；填充按钮前景单独配对 |
| selection-bg | `#EAF1FF` | `#223653` | 选中行与导航 |

新增 `accent-foreground`、`focus-ring`、`surface-pressed`、`disabled-text`、`disabled-bg` 及各语义状态的前景 / 背景组合。不要把 accent 色同时无条件用于正文和按钮底色；深色按钮必须单独验证文字对比度。

常规可读正文与说明文字目标至少 4.5:1；大字、关键控件边界与焦点按适用场景验证至少 3:1。现有测试只要求 supporting text 3:1，需提升关键说明文字的标准；真正禁用状态与正文分开处理。

### 5.2 字体、尺寸和间距

| 类型 | 推荐 |
| --- | --- |
| 页面标题 | 22–24 / medium 或 semibold |
| 分组标题 | 15–16 / medium |
| 正文、按钮、列表主文本 | 13–14 |
| 说明、时间、次级标签 | 12–13，不用过淡文字承载关键信息 |
| 路径、IP、端口、启动参数 | 局部等宽；中文名称保持 UI 字体 |
| 间距刻度 | 4 / 8 / 12 / 16 / 24 / 32 |
| 按钮与输入高度 | 默认 34–36；紧凑图标按钮 28–32 |
| 圆角 | 控件 6，列表容器 8，弹窗 10–12；状态标签可胶囊形 |
| 分隔与阴影 | 列表细分隔线；阴影只用于菜单、弹窗等浮层 |

优先使用平台 UI 字体并验证中文回退，避免新字体依赖。数字数量与时间使用等宽数字。整行数据不各套一个厚边框卡片，主要靠对齐和留白分层。

## 6. 图标与细节规范

先检查 GPUI Kit 已有的 Icon / IconName 和资源加载能力，优先复用同一图标集。缺失时引入同一版本、许可可核验的 Lucide 风格本地 SVG；下列为语义参考名，并非保证当前库有同名枚举。

| 场景 | 图标语义参考 | 展示方式 |
| --- | --- | --- |
| 浏览器环境 | PanelsTopLeft / LayoutGrid | 图标加导航名称 |
| 代理 | Network / Globe | 图标加导航名称 |
| 浏览器内核 | Cpu / Box | 图标加导航名称 |
| 活动日志 | ScrollText / List | 图标加导航名称 |
| 设置 | Settings | 图标加导航名称 |
| 新建 | Plus | 图标加“新建环境”等明确文字 |
| 启动 / 停止 / 重启 | Play / Square / RotateCw | 行主动作带文字；重启放更多菜单 |
| 更多 / 编辑 / 复制 | Ellipsis / Pencil / Copy | 更多常驻；菜单项图文并用 |
| 检测 / 校验 | Activity / ShieldCheck | 清楚区分代理测试与指纹校验 |
| 文件夹 / 删除 | FolderOpen / Trash2 | 菜单图文；删除与普通操作分隔 |
| 提示 / 错误 / 关闭 | Info / CircleAlert / X | 辅助说明、状态或浮层关闭 |

- 操作图标 16，导航图标 18，空状态 32–40；同一组保持同一画布与笔画约 1.5–1.75 的视觉重量。
- 图标跟随文字颜色，避免各项导航一个彩色图标。禁止 Emoji、Unicode 符号替代实际图标；不要混用实心、描边和不同粗细。
- 图标按钮拥有完整命中区域；hover 有轻背景，pressed 加深，键盘 focus 有清晰轮廓。
- 所有无文字按钮都有本地化 tooltip 和可访问名称；“更多操作”针对对应环境，不只叫“更多”。说明同时支持悬停与键盘聚焦。
- 主要动作不只在 hover 出现；触摸板、键盘和非悬停设备同样可发现。
- 清除搜索的 X、关闭详情的 X 和窗口 X 保持视觉层级与作用范围清晰。
- 光学校准播放三角形、加号与文字基线，避免仅按 SVG 边界机械居中。

## 7. 逐页方案

### 7.1 浏览器环境

列表默认列：环境名称及内核摘要 / 代理 / 状态 / 操作。种子、完整平台、参数、进程与端口移入详情。代理“直连”明确显示，不用空白或减号替代。

| 运行状态 | 行主动作 | 反馈与限制 |
| --- | --- | --- |
| 已停止 | 启动 | 轻量强调按钮；不会同时显示禁用的停止按钮 |
| 启动中 | 按当前能力显示“取消启动” | 有 loading；沿用 `can_stop` 等真实能力，不凭 UI 假设可取消 |
| 运行中 | 停止 | 中性描边或轻背景按钮，重启进更多菜单 |
| 停止中 | 停止中… | 禁止重复触发 |
| 失败 / 崩溃 | 重试（仅可启动时） | 展示可理解的失败摘要，完整错误在详情 |

新建环境作为页面唯一高强调填充按钮；多行“启动”采用低一些的强调等级，避免一屏蓝色块。

更多菜单：编辑、复制环境、打开数据目录、校验指纹、重启；分隔后删除。菜单按业务能力禁用并说明原因，保留现有删除确认与运行限制。点击行内按钮不触发行选中或其他行事件。

详情分为“概览 / 启动参数 / 日志”，优先复用现有 DetailsTab。概览内分基本配置、运行信息、校验结果；校验块可展开更多读数。复制参数只放在参数标签附近，避免全局操作横排。关闭详情后焦点回到原行。

未校验、校验中、通过、不一致、读取失败分别显示，不能用“运行中”的绿色暗示指纹已通过。显示最后校验时间或过期含义时必须有真实时间数据支持。

### 7.2 代理

以名称、协议 / 端点、使用情况、最近测试结果、操作对齐。常驻“测试”及更多菜单；编辑、删除收进菜单。测试中有行内 loading，完成保留结果。

代理测试是一次连通与出口测量，不标记成永远“在线”。未测试、测试中、成功、失败分开；成功显示实际出口 IP，若后端已有耗时则可显示并明确“测试耗时”，不伪装成纯网络延迟。失败摘要支持查看诊断，不在行内堆完整底层错误。凭据不出现在列表和 tooltip。

链接导入弹窗使用多行文本区，格式提示放输入附近；解析错误指向具体项目。资源很多时再单独增加搜索，不把尚不存在的功能当成现有能力。

### 7.3 浏览器内核

列表优先展示名称、版本、兼容或能力摘要、使用数量，路径作为次级文本并可复制。文件不存在或版本未知用明确标签，不能与普通未选中状态混淆。

主动作“重新检测”，更多菜单放编辑、打开位置（需明确实现范围）和删除。兼容性详细说明展开阅读，界面文案避免直接依赖 `honoured` 等底层英文字符串。新增内核使用文件路径字段；若采用文件选择器，需先验证跨平台支持。

### 7.4 活动日志

保留现有级别过滤，顶部工具栏统一控件高度。行按时间、级别、环境、消息组织，长消息展开而非撑满所有行；日志路径收进低强调信息行，写入失败仍显著显示。

复制是常规动作，清空降为次级操作并明确清理范围，不能暗示删除磁盘日志。用户查看历史时不被新增日志强行滚回底部；如添加“跟随最新”，作为明确可控状态。消息文本可以选择和复制，完整信息可获得。

### 7.5 设置

页内采用轻量分组导航或锚点，先做四组，不增加第二套庞大的侧栏：

1. 常规：外观、语言、关闭窗口行为。
2. 运行环境：内核 / Xray 路径、探测地址、相关配置。
3. 数据与备份：配置导出、导入、恢复、浏览器数据备份与恢复。
4. 诊断与关于：诊断导出、日志与数据位置、版本、技术信息。

外观用浅色 / 深色带缩略预览的二选一控件；“跟随系统”只作为后续能力，不展示无法工作的选项。语言使用选择器。

配置值的“来自环境变量”等来源信息保留，收敛成轻量标签；被覆盖或不可编辑时直接解释原因。不得因简化页面隐藏有效值与保存值的区别。

数据恢复与普通导入必须分别解释影响；破坏性恢复放明确分区，目标路径和确认不能折叠到不可发现处。密码包含选项保留可见说明，不因视觉降噪省略。

### 7.6 新建 / 编辑表单

把长表单分为基本信息、指纹配置、高级选项。基础包含名称、内核、代理；常用指纹项可直接读到，高级覆盖值折叠，修改过的分组显示“已修改”提示。保留原模型和默认值，不因布局重组重新生成指纹。

内核和代理用可搜索选择器；3–4 个以内的固定枚举可用分段控件。资源失效时仍显示原绑定与问题，绝不静默切为直连。种子的重新生成靠近输入字段，编辑现有环境时明确说明改变身份的影响。

推荐宽 720–800，上限为窗口可用宽度减 48；小窗口转单列。标签置顶或统一对齐，长帮助文字按需展开，关键影响始终可见。保存和取消固定于底部；字段错误就地显示，提交后聚焦第一个错误；服务端错误保留在表单可见区域。标签、aria 名称和错误文本统一本地化。

## 8. 状态、反馈与可访问性

- 空状态三种分别设计：没有内核 → 添加内核；没有环境 → 新建环境；搜索无结果 → 清除搜索。一个简洁线性图标、一句原因、一个相关动作即可。
- 加载使用与动作绑定的 spinner，不制造假进度；取消等待与真正停止进程的文案按实际业务含义区分。
- 成功用短暂 Toast；用户需处理的失败在对应行或表单持久可见；日志保存完整原因。去除一次动作同时触发多条等价成功提示的情况。
- 删除确认写出对象名称与实际影响；“删除配置”和“删除浏览器数据”不能混淆。
- Tab 顺序与阅读顺序一致；菜单支持方向键、Enter、Esc，关闭后恢复焦点；选中行和键盘焦点视觉不同。
- 建议支持 Ctrl+F 聚焦已有环境搜索；其他快捷键逐一查平台冲突后再加。Esc 优先退出最上层浮层，不关闭主窗口。
- Hover / pressed 反馈约 100–140 ms，浮层过渡约 140–180 ms；减少动态效果偏好下关闭非必要动画。轮询状态更新不做反复闪烁或入场动画。
- 所有状态具有文字或图形辅助，不只用颜色区分；正常文字不因“高级感”而变浅到难读。

## 9. 工程落地

沿用当前 UI 与 AppState / application / runtime 的分层。组件只展示状态与派发动作，不把进程控制或生命周期判断搬进渲染代码。

### 与方案的偏差

1. 侧栏宽取 200（方案 192–208 区间内）；页头标题取 22px、分组标题 15px、控件高 34px。
2. 组件库默认主题的 primary 是中性的，因此 `theme::apply` 会覆盖 primary/ring/selection，使填充按钮与选中态统一为方案中的蓝色 accent。
3. 图标没有另建本地 SVG 集：缺失的 16 个图标通过 `icon_assets!` 从同一份 Lucide 目录内嵌，避免引入第二套画风与许可证核对成本。
4. 关闭对话框已按方案改造（图标 + 后果说明 + 计数句），但实机只能取到「无档案运行」的空闲形态：本环境下 Chromium 启动即 SIGTRAP 退出（无法建立 CDP），因此「有档案运行时」的计数句只有测试覆盖（`the_close_question_counts_what_is_running`），没有截图。
5. 停靠阈值取 1364 逻辑像素而不是方案里的「约 1280」：这是 200（侧栏）+ 48（页面内边距）+ 380（面板）+ 16（列间距）+ 720（列表）的和。取 1280 时列表只剩约 636，与方案自己要求的「主列表能保留至少 720」冲突，故以列表宽度为准。副作用是本机 1440 逻辑宽（2880 物理，DPR 2）的屏幕只有最大化时才会停靠。
6. 可搜索选择器在测试里不是点击驱动的：组件库的列表是虚拟列表，测试窗口不会给它做布局测量，弹出层里的行没有尺寸，所以行的 id 找不到（组件库自己的测试同样只用 `set_selected_value` 驱动）。测试因此通过选择器状态的公开 API 提交选择，验证「选择 → 保存的档案」这条接线；弹出层本身在实机窗口用截图复核（见 `p2-dark-form.png`）。
7. 面板宽度取 380、列表行高 64、页头与分组的字号沿用 P1 的基线，未再单独调整。
8. 日志不为「最新一行」强制滚动：列表是最新在上，新行出现在顶部而不是底部，因此不存在被强制拉回的滚动位置，方案里的「跟随最新」按此实现为「不自动滚动、也不打断阅读」。
9. 日志的截断按当前列宽（由窗口宽度算出，中文字符按两列计）而不是固定字符数：固定值在最大化窗口下仍会折行，在窄窗口下又会截掉本可显示整行的内容。实机截图里的长行即由「内核可执行文件缺失」的长路径产生的一行。
10. 代理测试的「成功」状态在实机截图中来自本机回环上的 SOCKS5 代理与地址端点（`127.0.0.1`）：这台机器没有可用的外部代理，因此出口 IP 是回环地址；状态机的四态与真实引擎启动路径都走的是生产代码（`runtime::diagnostic`），没有测试替身。
11. 焦点环与选中态是两套视觉：选中用 `selected` 底色 + accent 边（既有 P1/P2 设计），键盘焦点用组件库的 `focus_ring_style`（画在边框外的环）。同一行可以同时是两者，截图里能分辨；没有引入第二套「选中感」。
12. 空的内核目录在实机上不容易复现：启动时的内核发现会先在 `FP_BROWSER_CHROMIUM_BIN`、再在惯例相对路径、最后在 `PATH` 里找一个 chromium 并自动登记（本机是 `/usr/bin/google-chrome`），所以「没有内核」的空状态是刻意用 `PATH=/nonexistent` 起的实例才取到的。
